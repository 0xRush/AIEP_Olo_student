Reference copies of the artefacts labs produce, so a student who missed a day is not blocked the next
day.

## How it is used

`aiep.data.load_artefact` looks in the notebook's own `artefacts/` first, then falls back here:

```python
from aiep.data import load_artefact

features = load_artefact("features.parquet")
# ./artefacts/features.parquet  →  shared/solutions_cache/features.parquet
```

When the fallback is used, the student sees a bilingual note saying so — they should know they are
working from the reference copy, not their own output.

## The rule

**Providing a reference copy here is mandatory for every artefact a later lab consumes.** Record what
each lab produces and consumes in that week's `Lab_Specs.md`. A lab that hard-fails because yesterday's
output is missing is a broken lab.

Files here are committed (keep them small — sample if needed) and are the *instructor's* correct
output, generated by running the `_solution` notebook.

## `llm_cache/` — the one entry that cannot regenerate itself

W7D3 and W7D4 call a language model through `aiep.llm.chat`, which reads
`llm_cache/<hash>.json` before it reaches for a key. That is what lets both labs run with no
`OPENROUTER_API_KEY` and no network — the plan for the cohort where the Wi-Fi fails.

Every other file in this directory falls out of running a solution notebook. This one does not: a
cold cache needs a key *and* a network, so it has to be generated deliberately and committed.

```bash
cp .env.example .env            # and fill in OPENROUTER_API_KEY
make verify-notebooks           # or run W7D3 and W7D4 top to bottom, unedited
mkdir -p shared/solutions_cache/llm_cache
cp week_*/labs/*/artefacts/llm_cache/*.json shared/solutions_cache/llm_cache/
```

The cache key is a hash of the exact request — model, system prompt, user prompt, temperature,
token limit — so **editing a prompt invalidates its entry**. Change a prompt, regenerate, recommit.

`make lint-llm-cache` (in `make lint`, and in CI) fails while this directory is missing or empty.

## مجلّد `llm_cache/` — المدخل الوحيد الذي لا يولّد نفسه

يستدعي معملا الأسبوع السابع اليوم الثالث والرابع نموذجًا لغويًا عبر `aiep.llm.chat`، وهي تقرأ
`llm_cache/<hash>.json` قبل أن تطلب المفتاح. وهذا ما يتيح للمعملين العمل بلا مفتاح وبلا شبكة، وهو
الخطة لأي دفعة تتعطّل فيها الشبكة.

وكل ملف آخر هنا ينتج عن تشغيل دفتر الحل، أما هذا فلا: فالذاكرة الفارغة تحتاج مفتاحًا وشبكة معًا،
فيجب توليدها عمدًا وإيداعها في المستودع بالأوامر أعلاه.

ومفتاح الذاكرة بصمة للطلب بالضبط — النموذج ونص النظام ونص المستخدم ودرجة الحرارة وحدّ الرموز —
فتعديل أي طلب يُبطل مدخله. غيّرت طلبًا؟ أعد التوليد وأعد الإيداع.

ويفشل الأمر `make lint-llm-cache` (وهو ضمن `make lint` وضمن التكامل المستمر) ما دام هذا المجلّد
مفقودًا أو فارغًا.
